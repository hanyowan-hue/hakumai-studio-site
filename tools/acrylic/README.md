# acrylic_check — アクリル入稿 SVG の検査・加工ツール

アクリル板で作る結婚証明書のように、**同じ形のパーツを何十個も並べる**データ向けの検査ツールです。
「どのパーツも同じ穴にパズルのようにはまるか」を、目視ではなく数値で確認します。

すべての計測は **mm** で行います（`viewBox` と `width`/`height` から換算）。

## できること

| コマンド | 内容 |
|---|---|
| `info`   | 輪郭の一覧・実寸・入れ子の深さを表示 |
| `shapes` | 同じ形のパーツを自動でグループ化し、**拡大縮小・歪み・鏡像**を分けて検出 |
| `holes`  | 四隅に同じ直径・同じ角からの距離でネジ穴を追加し、書き出し後に実測して検証 |
| `names`  | SVG のテキストと Excel / CSV の名簿を突き合わせ |

## 準備

```bash
pip install svgpathtools numpy openpyxl
```

`openpyxl` は Excel の名簿を読むときだけ必要です（CSV なら不要）。

## 使い方

```bash
cd tools/acrylic

# まず中身を見る
python3 -m acrylic_check info 入稿.svg

# カット線の検査（カット線レイヤーだけに絞る場合は --layer）
python3 -m acrylic_check shapes 入稿.svg --layer 'カット|cut' \
    --dev-tol 0.10 --scale-tol 0.2 \
    --overlay NG確認.svg --json 結果.json

# 四隅にネジ穴（直径 4mm、辺から 12mm）
python3 -m acrylic_check holes 入稿.svg -o 入稿_ネジ穴.svg --diameter 4 --inset 12

# 名前の照合
python3 -m acrylic_check names 入稿.svg --roster 参列者.xlsx --column 名前
```

`shapes` と `names` は NG があると終了コード 1 を返すので、
入稿前チェックとして自動化できます。

Colab で使う場合は `colab_acrylic_check.ipynb` を開いてください
（ファイルをアップロードして順に実行するだけです）。

## `shapes` の読み方

```
---------- 形1（20 個, 入れ子の深さ 1） ----------
基準: cut_sub020  30.630 × 29.437 mm
    名前                                  倍率      ズレ最大mm    ズレRMSmm    鏡像  判定
    cut_sub005                     1.01500      0.2513     0.1450        ❌ 拡大縮小 +1.500% / 形のズレ 最大 0.251mm
    cut_sub009                     1.00000      0.0000     0.0000    あり  ❌ 鏡像（裏返し）
    cut_sub021                     1.00000      0.0000     0.0000        OK
```

- **倍率** … 基準パーツの何倍か。`1.00000` なら拡大縮小なし。
- **ズレ最大 mm** … 基準にぴったり重ねたときの、輪郭上の最大のズレ。
  実際に「穴にはまるか」はこの値で判断します。
- **ズレ RMS mm** … 同じく平均的なズレ。
- **鏡像** … 裏返さないと重ならない（＝同じ穴に入らない）。

判定は次の 3 つを独立に見ています。

| 見ているもの | 判定に使う値 | 既定の許容 |
|---|---|---|
| 拡大縮小 | 最適な相似変換のスケール | ±0.2%（`--scale-tol`） |
| 歪み | 重ねたあとに残るズレ | 0.10mm（`--dev-tol`） |
| 鏡像 | 反転しないと合わないか | 不可（`--allow-mirror` で許可） |

### 許容値の決め方

レーザーカットのカーフ（切りしろ）と位置決め精度を考えると、
はめ合いを気にする用途では **0.1mm** 前後が目安です。
まず既定値で流し、NG が多すぎる場合は `--dev-tol 0.2` のように緩めて
「どの程度のばらつきが現状あるか」を先に把握してください。

`--samples` を増やすと細部まで見ますが、その分ノイズも拾います（既定 512）。

### グループ分けについて

同じ形のパーツは自動でグループ化されます。挙動を変える主なオプション：

- `--shape-tol` … 同じ形とみなす閾値（無次元、既定 0.02）。
  意図したグループに分かれないときはここを調整します。
- `--max-scale-ratio` … 寸法比がこれを超えるものは比較対象にしません（既定 1.25）。
  板の外形とネジ穴のような「大きさが桁違いのもの」を
  同じグループに入れてしまう事故を防ぎます。
- `--ignore-depth` … 既定では入れ子の深さ（外形／パーツ／穴）ごとに分けて比較します。
  これを外して深さを無視したいときに指定します。

同じ形が 1 個しかないものは「単独の形」として別枠に表示されます。
**比較対象がないので OK とは言えない**ためです（板の外形やネジ穴がここに出ます）。

## `holes` について

- 基準の矩形は既定で「最大面積の輪郭」（＝板の外形）のバウンディングボックスです。
  `--rect-mode all` で全図形の外接矩形、`--rect x,y,幅,高さ` で mm 直接指定もできます。
- `--inset` は**辺からの距離**です。X と Y を変えたい場合は `--inset-x` / `--inset-y`。
- 書き出したファイルを**読み直して実測**し、4 つの直径と角からの距離が
  揃っているかを表示します。ここが ✅ でなければ出力を使わないでください。
- 同じ `--layer-id` で再実行すると、前回のネジ穴レイヤーを貼り替えます（増えません）。
- 追記はテキストとして `</svg>` の直前に挿入するだけなので、
  **既存のパスデータは 1 バイトも変わりません**。

## `names` について

名前が **テキストレイヤーとして残っている** データが必要です。
画像に焼き込んだり、アウトライン化したデータからは文字を読み取れないため、
その場合はその旨を警告して終了します。

入稿用にアウトライン化する場合でも、**アウトライン化する前のデータで一度照合する**
運用にしてください。照合オプション：

- `--column` … 名簿の列名（または 0 始まりの列番号）
- `--strip-spaces` … 「山田 太郎」と「山田太郎」を同一とみなす

全角・半角、記号のゆれは NFKC 正規化で吸収し、連続する空白は 1 個に潰します。

## テスト

```bash
python3 tests/test_acrylic_check.py     # pytest なしで動きます
```

わざと欠陥（1.5% 拡大 / 鏡像 / 縦 2% 引き伸ばし / 局所変形）を入れたサンプル SVG を生成し、
**その 4 件だけが NG になること**、正常なサンプルでは **NG が 0 件になること**を確認します。

サンプル SVG を手元で見たい場合：

```bash
python3 tests/make_sample.py            # tests/sample/ に good.svg と bad.svg
```

## 入稿にあたっての注意

- 本ツールは検査対象の SVG を**書き換えません**（`holes` の出力先だけが例外で、
  それも追記のみ）。
- カット線のレイヤー名やスウォッチ名は入稿先の指定に合わせて残してください。
  `id` を機械的に振り直すと、`<use>` や `clip-path` の参照が壊れます。
- `xml.etree.ElementTree` でそのまま書き戻すと名前空間が `ns0:` に変わります。
  SVG を書き出す処理を足すときは `ET.register_namespace("", "http://www.w3.org/2000/svg")`
  を忘れないでください。
