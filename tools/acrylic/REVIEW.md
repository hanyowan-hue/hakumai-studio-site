# 既存 Colab ノートブックのレビュー

対象：`svg チェック` ノートブック（① アップロード / ② 連番振り / ③ 形状分類＋サイズ比較 / ④ ダウンロード）

結論から書くと、**このコードは「同じ形のパーツが同じ形か」を検査できていません。**
検査しているのは「グループ分けしたあとの外接寸法が揃っているか」だけで、
肝心のカット線そのものは一度も突き合わせていないためです。
以下、実際に再現して確認した内容を、影響の大きい順に挙げます。

---

## 致命的：検査として成立していない点

### 1. 形の比較をしていない（外接寸法しか見ていない）

`make_signature` は**グループ分けのため**にしか使われず、
OK / NG の判定は `oriented_size`（外接寸法）の差だけで決まります。

外接寸法が同じでも形が違うことはいくらでもあります。実際に確認した例：

| ケース | oriented_size の差 | 実際 |
|---|---|---|
| 円の一箇所を 8mm えぐった | **0.0000mm** | 明らかに別物 |
| 左右反転（鏡像） | **0.000mm** | 同じ穴にはまらない |

パズルのようにはめたいのであれば、外接寸法ではなく
**輪郭どうしを重ねたときのズレ量**を見る必要があります。

### 2. 鏡像（裏返し）を検出できない

`make_signature` は `np.abs(np.fft.rfft(radial))` を使っています。
絶対値を取ると鏡像に対して不変になるため、裏返したパーツは
「同じ形・同じサイズ」＝ **OK** と判定されます。

実測：左右反転させた花の signature 距離 = **0.00161**（閾値 0.035 以下 → 同じ形）。
サイズも当然同じなので OK が出ます。

アクリルの部品は裏返すと（左右対称でない限り）同じ穴に入りません。
これは見逃してはいけない不良です。

### 3. 不良品ほど検査をすり抜ける（グループ 1 個 = 常に OK）

判定の基準値は `np.median(major_values)` ―― **そのグループ自身の中央値**です。
そのため、形が崩れたパーツは signature 距離が閾値を超えて
**単独のグループに分離** → 中央値＝自分自身 → 差 0 → **OK** になります。

実測：円の一箇所を 8mm えぐった図形は signature 距離 1.0 で別グループに分離し、
そのまま OK と表示されました。**一番見つけたい不良が一番検出されない**構造です。

### 4. スケール不変なので、無関係な図形どうしを比較して誤検出する

`make_signature` は `pts = pts / mean_r` でサイズを正規化します。
その結果、**大きさが 10 倍違っても「同じ形」**になります。

ノートブックの実行結果の「形4」がまさにこれです。

```
---------- 形4 ----------
個数: 2
基準サイズ: 602.3660 × 602.3610
001 | その他_001_sub001 | 106.3020 × 106.3020 => ❌ NG
002 | その他_001_sub005 | 1098.4300 × 1098.4200 => ❌ NG
```

106 と 1098、つまり **10 倍違う 2 つの円** が同じグループに入り、
その中央値（＝平均 602.37）を基準にした結果、両方が NG になっています。
これはデータの不良ではなく、分類の誤りによる**偽 NG** です。
実際には「板の外形」と「ネジ穴のような小さな円」のように、
別物として扱うべき 2 つだったはずです。

### 5. `SIZE_TOL = 0.05` の単位が不明

`0.05` は SVG のユーザー単位です。ユーザー単位が mm なのか px なのかは
`viewBox` と `width` / `height` から計算しないと決まりません。
この SVG は 1 単位 ≒ 0.2646mm（96dpi の px）の可能性が高く、その場合
`0.05` は **0.013mm** という現実離れした厳しさになります。逆のケースもあり得ます。

入稿データの検査は「何 mm ずれているか」で判断すべきで、
**測る前に mm へ換算する**必要があります。

## 手法上の弱点

### 6. 角度ビンごとの「最大半径」は凹形状を表現できない

```python
for i, r in zip(idx, radii):
    radial[i] = max(radial[i], r)
```

半径が角度に対して一価でない形（花びらの深い切れ込み、葉の付け根など）では、
内側の輪郭が捨てられます。今回のモチーフはまさにこの形です。

さらに、**円に近い形では `radial` がほぼ定数**になり、
`sig` の中身が丸め誤差だけになります。それを
`sig / np.linalg.norm(sig)` で正規化するので、
**ノイズを単位ベクトルに引き伸ばした無意味な特徴量**になります。

### 7. `oriented_size` の PCA は回転対称な形で不安定

5 弁の花のように回転対称性がある形は共分散行列がほぼ等方になり、
固有ベクトルの向きが数値誤差で決まってしまいます。

実測（同一の 5 回対称図形を回転させただけ）：

```
  0度 → 24.7466 × 24.5618
  7度 → 24.7631 × 24.5372
 19度 → 24.7164 × 24.6039
 41度 → 24.8392 × 24.3894   ← 長辺のばらつき 0.1228
```

同じ図形なのに寸法が変わります。PCA ではなく
**凸包＋回転キャリパーによる最小面積外接矩形**を使うべきです。

### 8. `path.point(t)` は等弧長サンプリングではない

`svgpathtools` の `point(t)` はセグメントごとの等パラメータです。
セグメントの分割位置が違うパスどうしでは点の分布がずれるため、
点対応を取る比較には使えません。**弧長で等間隔に取り直す**必要があります。

### 9. グループ分けが順序依存で連鎖する

```python
for group in shape_groups:
    ref = group[0]                      # 最初に入った 1 個が基準
    if dist <= SHAPE_DISTANCE_TOL:
        group.append(obj); break        # 最初に当たったグループへ
```

先頭要素を基準にする貪欲法なので、入力順で結果が変わります。
また A—B が近く B—C が近ければ A—C が遠くても同じグループに入ります
（連鎖）。基準は**メドイド**（グループ内で最も中心的な要素）にすべきです。

### 10. サブパスを全部「独立したパーツ」として扱っている

複合パスのサブパスには「板の外形」「パーツの外形」「パーツに開いた穴」が
混在します。入れ子関係（どれがどれの内側か）を見ずに同列に比較すると、
4 のような事故が起きます。

## 入稿データを壊しかねない点

### 11. `ET.write()` が名前空間接頭辞を書き換える

`xml.etree.ElementTree` は名前空間を登録せずに書き出すと `ns0:` を付けます。実測：

```xml
<ns0:svg xmlns:ns0="http://www.w3.org/2000/svg" xmlns:ns1="http://www.w3.org/1999/xlink">
  <ns0:use ns1:href="#p" x="1"/>
```

`xlink:href` が `ns1:href` になります。読める環境も多いですが、
**入稿先の RIP や Illustrator で参照が解決されない**リスクがあります。
最低限 `ET.register_namespace("", "http://www.w3.org/2000/svg")` が必要です。

### 12. `subpath.d()` の再シリアライズでパスデータが変わる

```
元 : M 10.123456789,20.987654321 C ... Z
後 : M 10.123456789,20.987654321 C ... L 10.123456789,20.987654321
```

`Z`（クローズパス）が**始点への直線に置き換わります**。
検査対象そのものを書き換えてしまうため、確認用 SVG を作るときは
**元のパスに触らず、上に重ねるだけ**にすべきです。

### 13. `id` の総入れ替えで参照とレイヤー名が壊れる

`TARGET_TAGS` に `use` が含まれており、`elem.set("id", new_name)` で
すべての `id` を振り直しています。`<use xlink:href="#...">`、`clip-path`、
`fill="url(#...)"` などの参照は**すべて壊れます**。

また、`id="カット線"` という**入稿先が見るレイヤー名**が
`その他_001` に置き換わっています。アクセアのような印刷会社に出す場合、
カット線のレイヤー名／スウォッチ名は指定どおりに残す必要があります。

### 14. 分類ルールが今回のファイルに対して何もしていない

`CATEGORY_RULES` は 44 パターン作られていますが、実際のファイルは
`path` が 1 本だけなので、全部「その他」になります（実行結果のとおり）。
現状は死んだコードで、`ZERO_PAD` も `FFT_KEEP` の値も効いていません。

## 細かい点

- `except:` の裸捕捉が 4 箇所あります（`sample_path`、`oriented_size` ほか）。
  `KeyboardInterrupt` まで飲み込むうえ、点が欠けても気づけません。
- `sample_path` は `t = i/n` で `t=1` を含まないので、開いたパスの終点が落ちます。
- `parse_transform` が `skewX` / `skewY` に未対応です。歪みを検査したいのに、
  歪みを生む変換を無視しています。
- ルートの `viewBox` → `width`/`height` の写像を適用していないため、
  座標が実寸になっていません（5 と同じ問題）。
- セル ⑤ が同じコードを 2 回貼っており、ダウンロードが 2 回走ります。
- `base_name` がファイル名用とカテゴリ名用で紛らわしく併存しています。

---

## 良い点

- 複合パスを `continuous_subpaths()` でサブパスへ分割している着眼は正しいです。
- transform を親から合成して積む構造（`parent_matrix @ local_matrix`）は正解です。
- NG を赤で可視化して目で確認できるようにする発想は、入稿前チェックとして有効です。
- 判定を出したあとに「NG 数」と「赤く塗れた数」を突き合わせている点は良い習慣です。

## この検査に必要な考え方

「同じ形か」は、次の 3 つを**分けて**測ると判断できます。

| 見たいこと | 測り方 |
|---|---|
| 拡大縮小されていないか | 最適な相似変換のスケール係数が 1 か |
| 歪んでいないか | 相似変換で重ねても消えない残差（mm） |
| 裏返っていないか | 鏡像にしないと重ならないか |

本ディレクトリの `acrylic_check` はこの方針で実装し直したものです。
輪郭を弧長で等間隔サンプリングして複素数列とみなし、
巡回相互相関の最大値から「始点のズレ・回転・スケール」を閉形式で求めて重ね、
残ったズレを mm で報告します。詳細は `README.md` を参照してください。
